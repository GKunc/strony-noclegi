# seo

Run `node tools/check.mjs` first: it already enforces missing config values, filler copy, one `<h1>`, `lang`, unique titles, title/description length, canonical, img alt/width/height, valid JSON-LD and FAQ schema matching the visible FAQ. The sitemap, canonical URLs and blog wiring (index, feed, llms.txt) are generated by the build. Then review what a script cannot judge:

## Classic SEO (each page and post)
- Title: primary keyword near the start, unique, 30-60 chars incl. brand. Meta description 120-155 chars with a reason to click.
- One `<h1>` with the primary keyword; h2/h3 follow the questions people actually search.
- Open Graph + Twitter tags complete; `og.png` is on-brand (regenerate with `node tools/make-assets.mjs`).
- JSON-LD: Organization + WebSite on home; Service/Product/LocalBusiness when the brief supports it; BlogPosting + BreadcrumbList on posts; FAQPage only for a real visible FAQ. Validate tricky cases at https://validator.schema.org.
- Images: `alt`, explicit width/height, `loading="lazy"` below the fold, hero image `fetchpriority="high"`, AVIF/WebP via `<picture>`, sized to display size.
- Internal links: home ↔ posts, posts ↔ related posts, descriptive anchor text, every post links to the CTA.
- Core Web Vitals: LCP < 2.5 s, CLS < 0.1, INP < 200 ms. No web fonts unless the brief requires them (then self-host, `font-display: swap`, preload one file).

## AI search (ChatGPT, Perplexity, Claude, Google AI Overviews / AI Mode)
- **Answer first.** The first paragraph of every page/post answers the main question in 1-2 plain sentences that make sense when quoted alone.
- **Clear entity.** Say explicitly what BRAND is, for whom and where, the same way on every page, in `llms.txt` and in the Organization schema; `sameAs` links to real profiles.
- **Quotable facts.** Specific numbers, prices, steps and definitions (only from the brief) in short paragraphs, lists and tables; cite sources for any statistic.
- **Question-shaped headings** matching how people ask assistants; a real FAQ where useful.
- **Freshness.** Visible "Updated" date + `dateModified` on posts, sitemap `<lastmod>` (automatic at deploy).
- **Experience and authorship.** Named author with a real bio/link on posts (E-E-A-T); first-hand examples beat generic advice.
- **Crawl access.** robots.txt allows OAI-SearchBot, ChatGPT-User, PerplexityBot, Claude-SearchBot and Bingbot; content is in the HTML, not injected by JS.
- **Bing matters for ChatGPT.** IndexNow runs on every deploy; make sure the site is verified in Bing Webmaster Tools (`publish` skill).
- `llms.txt` is accurate and lists every post with a one-line description.

## Verify
Chrome DevTools MCP: Lighthouse (mobile), performance trace, console errors, network failures, 375px emulation. CI runs Lighthouse too and fails below 0.9 performance / 0.95 accessibility, best practices and SEO.
Report findings as a short prioritized list, then fix the high-impact ones.
